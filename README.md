## Версия 0.1.2

- Фото и файлы прикрепляются кнопкой «＋», перетаскиванием или вставкой изображения через Ctrl+V в поле чата/задачи. Для вставки поддерживаются PNG, JPEG, WebP, GIF и BMP до 20 МБ.
- Миниатюры находятся внутри поля ввода. После отправки вложения сохраняются рядом с сообщением в локальной истории; нажатие открывает увеличенный просмотр. Старые сообщения без записанных сведений о вложениях остаются текстовыми.
- Запросы длиннее 12 000 символов передаются через файл message.txt. Текстовые вложения читаются полностью, без обрезания до предпросмотра.
- Подтверждение загрузки ожидается до 120 секунд и учитывает новые миниатюры в поле Google. Повторная попытка с тем же набором не загружает файлы повторно до отправки.
- При CAPTCHA открывается Chrome и показывается уведомление; после ручной проверки приложение продолжает работу и возвращает фокус своему окну.
- Протокол модели содержит требования к JSON summary/done/actions без назначения брендированной роли. Переходы панелей и появление сообщений анимированы с учётом системного уменьшения движения.
- Применение правок подтверждается в отдельном окне; повторные запросы не ставятся в очередь. Перед записью проверяется, не изменил ли пользователь исходные файлы.

## Рабочее пространство IDE

Слева находятся сохранённые проекты, задачи и чаты с общим поиском. По центру — запрос, общий прогресс, DAG и результаты этапов; ввод закреплён снизу. Число работников 1–50 и редактор плана находятся в меню «Агенты» рядом с вводом. Ctrl+Enter запускает задачу, Ctrl+N открывает новую. Ширину боковой панели и правого инспектора можно менять перетаскиванием разделителя или его стрелками; размеры сохраняются локально.

Кнопка «Файлы и терминал» открывает инспектор. Вкладка «Файлы» показывает список изменений и unified diff с номерами строк и базовой подсветкой синтаксиса. «Действия» показывает сообщения о состоянии, пояснения модели, фактические вызовы инструментов, результаты и ошибки. Это доступные ответы и действия, а не скрытая цепочка рассуждений модели. Протокол модели не исполняется как JavaScript/HTML.

«Терминал» отображает команды и результаты проверок. Ручной запуск принимает программу и JSON-массив аргументов, запрашивает отдельное подтверждение и работает в новой изолированной копии выбранного проекта. Это ограниченный по времени журнал команд, без интерактивного PTY и ввода в запущенный процесс. Отмена завершает принадлежащий приложению процесс и его дочерние процессы. Изменения ручной команды не включаются в агентский diff автоматически.

После сбоя кнопка «Повторить незавершённые этапы» сохраняет успешные результаты и исходный снимок, перезапуская оставшиеся этапы с новыми ID. Повтор доступен для текущей задачи до закрытия приложения. Сохранённые завершённые задачи можно открыть и применить после перезапуска. Применение открывает отдельное окно с путём проекта, diff и подтверждением; после записи сохраняется статус «Изменения применены». Автоматическое восстановление исполнения архивных этапов не предлагается. При устойчивой квоте сервиса повтор не предлагается. Заблокированные зависимости показываются нейтрально, отдельно от настоящих ошибок.

`data/workbench.json` хранит выбранный проект и недавние проекты; история чатов остаётся в `data/history.json`, отчёты задач — в `data/agent_runs`. При первом переходе на новый интерфейс проект восстанавливается из последнего отчёта. Открытие IDE не создаёт браузерных бесед: подключение происходит при запуске задачи или открытии обычного чата. Пул использует один процесс Chrome и ограниченное число анонимных контекстов; отдельные контексты Chrome может показывать отдельными окнами. CDP-транспорт принимает только локальные WebSocket-адреса. Это не VPN, DNS-фильтр или песочница ОС.

Проверки интерфейса: `node --test tests/adapter.test.cjs tests/workbench.test.cjs tests/desktop-ui.test.cjs`.

## Агенты для разработки

Оконная версия открывает панель Coding agents. Выберите папку проекта, задайте запрос и число работников ползунком **1–50** (по умолчанию 3). Ползунок работает мышью и клавишами стрелок. Можно использовать стандартный план, отредактировать JSON DAG или запросить план у модели. Затем запустите задачу. Отдельно отображаются заданное число работников, активные задачи и очередь ожидания ресурсов. Изменение числа во время работы ограничивает новые назначения; уже выполняющиеся задачи завершаются без потери изменений.

По умолчанию одновременно работают только **две независимые анонимные беседы в одном Chrome**, запросы разделены общим интервалом 5 секунд. Количество работников не создаёт столько же экземпляров браузера. Зависимые задачи ждут предшественников. При HTTP 429 действует общая пауза с учётом Retry-After; повтор используется в той же сессии. Устойчивое ограничение останавливает оставшуюся работу, без смены сессий ради обхода квоты. Авторизация в Google не обязательна; доступность анонимного AI Mode определяется самим Google.

Каждая задача получает частную копию снимка проекта с собственным Git-каталогом. Снимок включает текущие незакоммиченные изменения и разрешённые неотслеживаемые файлы; зависимости передают проверяемые изменения следующим задачам. Параллельные конфликтующие правки отклоняются. Исходная папка меняется только после просмотра diff и отдельного подтверждения Apply. Хеши исходных файлов повторно проверяются перед применением, чтобы не затереть ваши новые правки.

Инструменты реально читают и ищут файлы, создают текстовые и бинарные файлы в копии, формируют diff, применяют unified patch, запускают сборки/тесты и Git. Команды, удаление файлов, применение patch и итоговая запись в исходный проект требуют явного решения пользователя. Подтверждение показывает точные аргументы и рабочую папку. **Одобренная команда выполняется на компьютере пользователя: копия проекта не является песочницей ОС.** Команда или код сборки могут обращаться вне копии; проверяйте их перед одобрением. Модель и содержимое репозитория не могут выдавать разрешения. Прямые файловые инструменты запрещают выход из рабочей папки, ссылки/junction, секретные каталоги и неоднозначные Windows-пути.

Прикрепляйте несколько файлов через диалог, пути или перетаскивание в окно. Доступны метаданные, предпросмотр, проверка размера и SHA-256. Предпросмотр текстовых документов и исходников добавляется в контекст, полное содержимое доступно агенту порциями через read_attachment; PDF, изображения и DOCX передаются через файловый элемент страницы, только если текущая сессия Google его поддерживает. При отсутствии загрузки отображается ошибка. Файлы хранятся локально как неизменяемые копии; учитывайте, что выбранное содержимое отправляется Google. Типовой предел — 20 MiB на вложение. Сгенерированные файлы включаются в итоговый diff и сохраняются через Apply.

Настройки: `data/agents.json` (workers, max_sessions 1–8, интервалы, тайм-аут, число шагов/повторов, размер вложений). Отчёты, журналы бесед и изолированные копии: `data/agent_runs/`; вложения: `data/attachments/`. Эти данные остаются локально и исключены из Git. Автоматического возобновления незавершённой задачи после закрытия приложения пока нет.

Тот же движок доступен в Ratatui:

```powershell
cargo run --locked --bin gemini-cdp-cli -- --agents
```

`Tab` переключает фокус ползунка; стрелки, Home/End и мышь меняют число работников. `/workspace ПУТЬ` выбирает проект, `/attach ПУТЬ` прикрепляет файл, `/plan ФАЙЛ` загружает DAG, `/plan-ai ЗАПРОС` запрашивает план у модели. Ввод запроса запускает работу. F4 показывает вложения, F5 — diff, `/apply` запрашивает применение, Ctrl+A/Ctrl+D разрешают/отклоняют показанное действие, Esc отменяет работу, Ctrl+C завершает приложение. Перетаскивание путей зависит от поддержки bracketed paste терминалом.

Модули `src/agents/` содержат AgentManager, SessionManager, TaskScheduler, AgentWorker, ContextManager, ResultAggregator и EventBus. Tokio-задачи, bounded-очереди, семафор сессий, cancellation tokens и DAG отделяют выполнение от интерфейсов. `src/tools.rs` обеспечивает инструменты/изоляцию/подтверждения, `src/attachments.rs` — вложения, `src/agent_tui.rs` — терминальную панель. Существующий DOM/Markdown-парсер сохранён; для протокола инструментов добавлено отдельное декодирование JSON, включая экранирование Markdown.

Проверки движка:

```powershell
cargo test --locked --all-targets
node --test tests/adapter.test.cjs
cargo run --locked --bin gemini-cdp-cli -- --live-agent-smoke
```

Последняя команда обращается к Google с фиксированными публичными тестовыми данными: две независимые беседы читают файл, одна предлагает изменение; проверяется, что исходник не изменён без подтверждения. Обычные тесты не обращаются к сервису.

Лёгкий оконный интерфейс для **Google Search AI Mode**: графитовая тема, системный Mica/Acrylic, стеклянные панели, локальная история диалогов и потоковые ответы. Окно использует системный Microsoft WebView2, Rust и обычные HTML/CSS/JavaScript, без Electron, Node.js и внешних CDN во время работы.

## Оконная версия (Windows)

```powershell
cargo build --release --locked --bin evil-gemini
.\target\release\evil-gemini.exe
```

Или `cargo run`: по умолчанию открывается EVIL GEMINI. Нужен установленный WebView2 Runtime (обычно уже есть в Windows 10/11). Нативный Mica доступен на Windows 11; на поддерживаемых Windows 10 применяется Acrylic. Эффект можно выключить в настройках приложения. При отключённых системных эффектах прозрачности внешний вид может отличаться.

Для сборок Windows GNU файл `WebView2Loader.dll` автоматически копируется рядом с EXE. При переносе приложения сохраняйте эти два файла вместе, а `config.json` положите рядом с ними. HTML/CSS/JavaScript уже встроены в EXE.

- Новый чат: кнопка слева или `Ctrl+N`.
- Поиск по истории: поле слева или `Ctrl+K`.
- Отправка: `Enter`; новая строка: `Shift+Enter`.
- Копирование и повтор запроса: кнопки под последним ответом.
- Остановка ожидания: квадратная кнопка в поле ввода или `Esc`. Генерация в Google может продолжаться.
- Кнопка `Google AI Mode` показывает Chrome для входа/проверок; при отсутствии подключения повторяет попытку соединения.

История и параметры сохраняются в `data/history.json` в папке проекта; данные WebView2 — в `webview_data`. Эти папки исключены из Git. Ответы перед отображением преобразуются в Markdown/HTML с экранированием HTML модели. При переключении диалога восстанавливается сохранённый адрес Google. Если Google уже не может восстановить сессию, начните новый чат. Терминальную и оконную версии не следует использовать одновременно с одним браузерным профилем.

## Терминальная версия

Терминальный клиент для **Google Search AI Mode**. Chrome выполняет запросы к Google, Rust-приложение управляет вкладкой через локальный Chrome DevTools Protocol. Это автоматизация веб-интерфейса, а не официальный API Google и не локальная модель.

## Запуск

```powershell
cargo build --release --locked --bin gemini-cdp-cli
.\target\release\gemini-cdp-cli.exe
```

Запускайте из папки проекта: здесь читается `config.json`. В Chrome при необходимости вручную войдите в Google, подтвердите экран согласия или пройдите CAPTCHA. Доступность AI Mode зависит от Google, региона и аккаунта.

Chrome использует отдельный профиль `profile_ai_mode` и порт `9223`. Старый `profile_gemini` сохранён, его сессии не переносятся автоматически. При повторном запуске клиент подключается к вкладке Google Search на настроенном локальном порту. Не запускайте два CLI одновременно с одним портом: они будут управлять одной страницей. Если подходящей вкладки нет, закройте Chrome этого профиля и запустите клиент снова.

Каждый запуск терминальной версии открывает чистый диалог. Внутри сеанса уточняющие вопросы отправляются в ту же вкладку с сохранением контекста. История CLI хранится в памяти.

Управление:

- `Enter`: отправить; `Ctrl+J`, `Shift+Enter` или `Ctrl+Enter`: новая строка.
- `Ctrl+V`: вставить текст; `↑` / `↓`: прокрутка.
- `Ctrl+N`: открыть чистый диалог и очистить историю терминала.
- `Esc`: прекратить ожидание в CLI; генерация на странице может продолжаться.
- `Ctrl+C`: выйти. Chrome остаётся открытым.

В обычном терминальном чате поддерживается текст, включая код, списки, таблицы и ссылки. Для вложений и инструментов используйте `--agents`. Выбор модели через терминал не реализован; название модели и лимиты не подставляются предположительно.

## Конфигурация

`chrome_binary`, `profile_dir`, `cdp_port`, `headless` задают запуск браузера. `response_timeout_secs` ограничивает ожидание одного ответа (по умолчанию 180 секунд). На первом запуске используйте `headless: false`, чтобы пройти вход и другие проверки вручную.

Необязательный объект `ai_mode` позволяет переопределить `input_selector`, `response_selector`, `stop_selector`, `complete_selector`. Значения по умолчанию находятся в `src/ai_mode.rs`. Разметка Google может меняться — при этом адаптер потребует обновления.

DNS, VPN и маршрутизация этой переработкой не меняются. Chrome использует текущую сеть компьютера. CDP доступен локально; не публикуйте его порт в сеть.

## Проверка

```powershell
cargo test --locked
node --test tests/adapter.test.cjs
.\target\release\gemini-cdp-cli.exe --diagnose
.\target\release\gemini-cdp-cli.exe --smoke-test
```

`--diagnose` печатает структуру найденных полей/ответов без текста диалога и cookies. `--smoke-test` открывает чистый диалог и отправляет два фиксированных тестовых сообщения, проверяя ответ и память о токене `BLUEORBIT`. Этот режим обращается к Google и использует обычные лимиты сервиса.

## Архитектура

- `src/browser.rs`: запуск Chrome, обнаружение вкладки, CDP-команды, тайм-ауты транспорта и ошибки JavaScript.
- `src/ai_mode.rs`: готовность страницы, отправка, состояние одного запроса и завершение ответа.
- `src/ai_mode.js`: DOM-адаптер Google AI Mode и преобразование ответа в Markdown.
- `src/main.rs`: терминальный интерфейс и управление диалогом.
- `src/markdown.rs`: отображение Markdown с переносами строк.
- `src/desktop.rs`: нативное окно, IPC и фоновый обработчик диалогов.
- `src/history.rs`: история, настройки и безопасное преобразование Markdown.
- `ui/`: интерфейс EVIL GEMINI, встроенный в исполняемый файл.

Ошибки отправки сохраняют введённый текст. Ошибки чтения и тайм-ауты отображаются в строке состояния. При выходе, включая ошибки, восстанавливается терминал.

## Режимы управления и оценка текста

Верхний переключатель «Чат / Работа» сохраняет отдельные черновики. Диалоги и задачи отображаются в своей вкладке. Схема DAG сохранена; переключение в чат не прекращает работу агентов.

Режим доступа выбирается пользователем и сохраняется в `data/agents.json`:
- **Ask for approval** (по умолчанию): подтверждение команд, patch/удалений и применения исходников.
- **Approve for me**: автоматически разрешаются валидированные patch/удаления в копии и стандартные `cargo check/build/test` с ограниченным набором флагов; другие команды, Git и применение исходников требуют подтверждения. Сборки и тесты могут выполнять код проекта на компьютере.
- **Full access**: запросы инструментов выполняются без подтверждения. Прямые файловые инструменты по-прежнему ограничены рабочей папкой; host-команды не являются песочницей ОС. Итоговое применение подготовленного diff запускается отдельной кнопкой.

Изменение режима действует на следующие запросы и не подтверждает уже ожидающие действия автоматически. Модель не может выбирать или менять режим через протокол инструментов.

Счётчики используют приближение: один токен на четыре Unicode-символа. Для задачи учитывается текст отправляемых контекстов и ответов модели; для чата — видимая история и черновик. Это оценка объёма текста, не показание токенизатора, биллинга или остатка квоты Google. Синий ASCII-помощник расположен над полем ввода и не мешает выделению текста.

Диагностика отправки отличает старый busy-флаг от принятого нового запроса. Завершённый отказ Google в последнем блоке `aimfl` распознаётся отдельно как `SERVICE_REFUSAL`, без ожидания обычного ответа. Приложение не пытается обходить такой отказ сменой анонимных сессий. Даже корректный текст модели о завершении не засчитывается без успешного вызова инструмента.
